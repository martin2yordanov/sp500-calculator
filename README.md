# S&P 500 — Лихва върху лихва

Калкулатор за лихва върху лихва при периодични инвестиции в индексен фонд,
с живи цени на **SXR8** (iShares Core S&P 500 UCITS ETF, Xetra).

Един и същи код върви на три места: като сайт в Vercel, като PWA и като
native iOS приложение, опаковано с Capacitor.

## Стартиране

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # продукционен билд в dist/
npm test         # изчисленията и валидацията на настройки
```

`npm run dev` очаква `/api/sxr8` на `localhost:3000` (виж `vite.config.js`).
Най-лесно е с `vercel dev`, който вдига и статиката, и функциите заедно.

## iOS

```bash
npm run ios      # билд + sync + отваря Xcode
```

Пълните стъпки — Apple Developer портал, Clerk настройки, подписване и
качване в App Store — са в [`docs/IOS.md`](docs/IOS.md).

> Билдването на iOS изисква macOS с Xcode. Всичко останало (включително
> генерирането на иконите и на самия Xcode проект) работи и на Linux.

## Настройка на средата

Копирай `.env.example` в `.env.local` и попълни каквото ти трябва. Всички
променливи са опционални: без `VITE_CLERK_PUBLISHABLE_KEY` приложението просто
не предлага вход и работи изцяло локално.

| Променлива | Къде | За какво |
| --- | --- | --- |
| `VITE_CLERK_PUBLISHABLE_KEY` | бандъл | Включва входа. Липсва ли — няма и бутон. |
| `VITE_API_BASE_URL` | бандъл | Абсолютният адрес на функциите. **Задължителен за iOS.** |
| `CLERK_SECRET_KEY` | сървър | Проверява сесийните токени и пише настройките. |
| `CLERK_AUTHORIZED_PARTIES` | сървър | Кои `azp` claim-ове се приемат. |
| `ALLOWED_ORIGINS` | сървър | Допълнителни origin-и за CORS. |

## Запазване на настройки

Бутонът **Запази** пази стойностите на три места, според това какво е налично:

1. в `localStorage` — винаги;
2. в URL-а (`?y=&m=&i=&r=`) и в клипборда — само в уеб, където линкът върши работа;
3. в акаунта — ако потребителят е влязъл.

При зареждане URL параметрите имат приоритет пред запазените локално. Ако
потребителят влезе в акаунт, настройките от акаунта се изтеглят веднъж и
заместват текущите — това е смисълът на синхронизацията между устройства.
Стойности извън границите се ограничават, вместо да чупят изгледа.

## Автентикация

Входът е **опционален**: калкулаторът смята еднакво добре и без акаунт.
Акаунтът добавя само синхронизация на настройките.

Поддържат се Apple, Google и код по имейл. Кодът по имейл е основният път —
работи без пренасочвания и е еднакъв в уеб и в приложението. Данните за
потребителя живеят в Clerk; настройките му — в `privateMetadata` на същия
запис, така че изтриването на акаунта отнася и тях.

Вътре в iOS обвивката Clerk не може да ползва бисквитки: приложението се
сервира от `https://localhost`, а Clerk отговаря от друг origin. Затова в
native режим клиентският токен пътува в `Authorization` хедър и се пази през
`@capacitor/preferences` — виж `src/auth/clerkInstance.js`.
